UI5's `ResourceModel` is already wired into the app at
`manifest.json` → `sap.ui5.models.i18n`. Any TSX view can read it
via `{i18n>key}` bindings; nothing in the JSX runtime special-cases
i18n. The same binding strings you'd write in an XMLView work
verbatim in TSX.

Three patterns:

```tsx
<Title text="{i18n>sampleI18nHeading}" />              // static key
<Input placeholder="{i18n>sampleI18nInputPlaceholder}" /> // any string prop
```

**Parameterized messages** need the imperative
`ResourceBundle.getText(key, [args])` call:

```tsx
const bundle = (this.getModel("i18n") as ResourceModel).getResourceBundle();
const text = bundle.getText("sampleI18nGreetingNamed", [name]);
this._state.setProperty("/greeting", text);
// view: <Text text="{form>/greeting}" />
```

Why not `{i18n>sampleI18nGreetingNamed}` directly? String-form UI5
bindings don't substitute placeholders. Either bind through a
JSONModel like this sample, or attach a custom formatter via the
binding-info object form.
